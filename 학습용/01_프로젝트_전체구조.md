# Promotion Radar 프로젝트 학습 가이드

## 전체 데이터 흐름

`config/targets.json` → `scripts/crawl.py` → `crawler.py` → SQLite →
`export_collection_status.py` → `public/data/*.json` → React 화면 순서로 동작한다.

## 주요 Python 파일

### `scripts/crawl.py`
실행 진입점이다. 프로젝트 경로, 대상 URL 설정, SQLite 위치, 스크린샷 출력 위치를
정한 뒤 `run_crawl()`을 호출한다. 로직은 적고 실행 환경을 연결하는 역할이다.

### `src/vzw_promo_tracker/crawler.py`
핵심 수집기다. `urllib`로 HTML을 먼저 받고 실패하면 Playwright Chromium으로
재시도한다. `VisibleTextParser`는 script/style을 제외한 화면 텍스트를 만든다.
HTML SHA-256을 계산하여 동일 원문인지 확인할 수 있게 하고, 원문·텍스트·HTTP
상태·시각을 SQLite에 저장한다. 마지막에는 미국 Runner의 실제 렌더링 화면을
전체 페이지 JPEG로 저장한다.

### `src/vzw_promo_tracker/extract.py`
수집 텍스트에서 가격, 기간, Trade-in, New line, AC, TIV 같은 표현을 정규식과
문맥 창으로 찾는다. 가장 중요한 원칙은 근거가 없으면 추정하지 않고 N/C로
남기는 것이다. 잘못된 결과가 나오면 먼저 이 파일의 패턴과 문맥 범위를 본다.

### `src/vzw_promo_tracker/db.py`
SQLite 테이블을 만들고 연결한다. `crawl_runs`는 실행 단위, `source_snapshots`는
URL별 원문, `promotion_candidates`는 추출 후보를 보관한다.

### `scripts/export_collection_status.py`
최신 SQLite 실행을 브라우저에서 읽을 수 있는 JSON으로 축약한다. 원문 HTML은
공개하지 않고 URL, 해시, 수집시각, 상태, 스크린샷 경로를 내보낸다.

### `scripts/build_evidence_pack.py`
현재 정규화 프로모션을 CSV로 평탄화하고 JSON·수집 메타데이터와 함께 ZIP으로
묶는다. 분석가가 Excel 또는 Python에서 별도로 검증할 때 사용한다.

### `scripts/build_internal_package.py`
빌드된 정적 사이트와 소스, 설정, 테스트, 학습 문서를 사내 이전용 ZIP으로 묶는다.

### `scenario_runner.py` / `scripts/run_scenarios.py`
PDP에서 용량, 고객유형, Next steps, 회선 조건, 요금제를 순서대로 선택한다.
각 클릭은 접근성 속성 또는 selected CSS 상태로 성공을 검증한다. 단계별 롱샷과
요청값·관측값·오류를 동일한 `scenarioId` 아래 저장하며, 모든 필수 단계와 최종
가격이 확인된 경우만 `verified`로 분류한다.

## 주요 라이브러리

- `Playwright`: 실제 Chromium 렌더링, 동적 페이지 이동, 전체 화면 캡처
- `BeautifulSoup4`: HTML 구조 분석에 사용할 수 있는 파서
- `sqlite3`: Python 표준 내장 DB. 서버 없이 스냅샷 보관
- `re`: 가격과 프로모션 문구 패턴 추출
- `hashlib`: 원문 SHA-256 생성
- `json`, `csv`, `zipfile`: 화면 데이터와 배포 산출물 생성

## 문제를 찾는 순서

1. URL/모델이 틀리면 `config/targets.json`을 확인한다.
2. 화면은 맞는데 값이 빠지면 `extract.py` 패턴과 원문 텍스트를 확인한다.
3. 수집은 됐는데 UI에 없으면 `export_collection_status.py`와 JSON을 확인한다.
4. JSON은 맞는데 화면이 틀리면 `src/main.jsx`의 필터·정렬·표시 로직을 본다.
5. 스크린샷이 목록 화면이면 PDP target과 Playwright 선택 시나리오를 수정한다.

## 현재 한계

시나리오 실행 구조와 실패 격리는 구현됐지만 Verizon DOM이 바뀌면 단계별 selector
어댑터를 갱신해야 한다. Trade-in 기종·상태는 조합 수가 크므로 우선순위 generation
probe를 별도 배치로 운영해야 한다. 실패한 선택은 가격 데이터로 승격하지 않는다.
